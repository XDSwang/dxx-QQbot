# dxx-QQbot — 运行与部署

> 两个仓库分工：**公共库（本仓库）＝代码本体**（代码 + `services.json` 服务清单），
> **你的私有库 ＝数据**（真实配置值、运行记录、启动器 `bootstrap.py`）。
> 长期运行的是本仓库根目录的 `run.py`；私有库的 `bootstrap.py` 只在首次部署跑一次，
> 跑完拉起 `run.py`（手机 / Linux 用 `execv` 替换进程，Windows 用前台等待保证
> Ctrl+C 能传到），之后不再常驻。
>
> 路径一律按**项目根目录相对书写**，本文不写任何盘符，需要绝对路径时自己拼：
> 私有库根 → `bootstrap.py`、`update.cfg`（真实配置，进私有库 git）、
>   `bootstrap.cfg`（本机部署项，可选）、`services/wm-bot/config.txt`；
> 公共库根（启动器默认克隆到私有库目录下的 `dxx-QQbot/`）→ `run.py`、`update.cfg`、
> `services.json`、`wm-bot/python/data/config.txt`。
> **四个仓库地址只有一处权威：私有库根目录的 `update.cfg`（接口文件，一切接口地址都在这里对接）**，代码与模板里不写死账号或仓库名。
> 术语：GIT 语境里说的「源」指**仓库地址**，不是第三方数据接口；
> 后者是以后扩展、当前不生效。**判断和读写都走 GIT 指令，不需要任何密钥 / API / 第三方接口**。

## 一、运行流程（已经部署好的机器）

### 前置条件

- Python 3 与 git 可用；本机对两个私有库地址能免密 `git fetch` / `git push`
  （已保存 HTTPS 凭证，或已配好 SSH key，两种都行）。
- 本仓库根目录有 `update.cfg`（启动器从私有库**原样拷来**的一份，不进公共库 git），
  里面只有数据后端与仓库地址；权威那份在私有库根目录，随私有库 git 同步。
- `wm-bot/python/data/config.txt` 里有真实值（首次部署由私有库带过来，之后由服务端对账维护）。

### 启动

```bash
cd dxx-QQbot
python run.py
```

### 启动后依次发生什么

1. 读根目录 `update.cfg`，装配**纯 GIT 数据后端**：读用 `git show` 取私有库里的文件，
   回写就是 `git commit` + `git push`，不需要任何 API 或 token。
2. 启动自检：git、`services.json`、数据后端、GIT 双源拷贝连通性；
   有问题只告警，照常用本地版本继续运行。
3. 代码同步：用 GIT 指令把两个公共库都 `fetch` 拷贝下来，比 commit 版本选最新，
   本地领先不回退，`merge --ff-only` 落地；两个源都失败报「数据拉取异常」，作废本轮但不影响服务。
4. 按 `services.json` 拉起服务（当前只有 `wm-bot` → `wm-bot/python/qq_bot.py`）；
   服务崩溃在一个时间窗口内最多自动拉起 3 次，超过就如实记日志；
   窗口过期或代码更新后会重新给机会，不会永久不再拉起。
5. 每 10 秒做一轮更新判断（**私有库和公共库各盯各的版本**）：
   - 私有库：两个源都 `fetch` 拷贝下来，比版本选最新，数据读写也切到同一源；
     **HEAD 没变＝拷贝无内容变化＝不用更新**，本轮直接跳过。
   - 公共库：独立做一次双源版本轮询（为省流量降频执行，最长约 1 分钟内感知）。
     **只 push 了代码、私有库没动，也会触发同步与迁移**。
   - 一个源失败就用拷贝成功的那个，两个都失败报「数据拉取异常」，本地数据保持原样。
     同一轮的拷贝结果由所有服务共用，不重复 fetch。
6. 真有更新才做功：读私有库配置 → 以公共模板为结构基准、私有真实值为覆盖对账（`structure`）
   → 备份 / 迁移 → 造提交并 `git push` 回私有库 → 只停、迁、启被触发的那个服务。
   代码文件变了则 `run.py` 自重启换到新版。
7. 私有库 `config.txt` 被账号本人改过（网页或 `git push`）→ 下轮检测哈希变化
   → 按模板迁移并热重载；新字段留空，真实密钥不会被空模板冲掉。

### 日常改东西怎么生效

| 想改什么 | 在哪改 | 服务端怎么跟上 |
|---|---|---|
| 机器人配置 / 密钥 | 私有库 `services/wm-bot/config.txt`（网页改或 push） | 下轮拷贝发现新 commit，自动迁移 + 热重载 |
| 代码 | 本公共库，提交后 push 到主库（备用库镜像保持同步） | 独立的代码版本轮询发现新 commit，自动同步 + 迁移；私有库没动也会触发 |
| 加服务 / 多机分工 | `services.json`、`SERVICES_ENABLED`、`UPDATER_DATA_NAMESPACE` | 各服务独立信号，互不惊动 |

改完必须 push：本地提交没推上去，服务端 GIT 双源拷贝也拉不到。

### 停止与日志

- `Ctrl+C` 正常退出；日常请在公共库目录直接跑 `python run.py`，这样停止信号能
  一路传到服务进程。不要开第二个 `python run.py`：用户主目录
  `~/.dxx-updater/updater.lock` 用系统文件锁拦住（不再靠 pid 猜，手机重启后
  pid 复用不会误拒启动）；且同一个 AppID 只能有一条网关长连接。
  锁所在文件系统不支持 `flock`（手机共享存储常见）时会降级为无锁并记异常日志，
  不会因此拒绝启动。
- 流程日志 `data/updater_flow.log`、异常日志 `data/updater_error.log`、
  机器人收发日志 `wm-bot/python/data/bot_flow.log`、
  链路日志 `wm-bot/python/data/selfcheck_trace.log`。三份流程日志都是当天追加、
  重启不清空，跨天归档成同目录 `<名字>-YYYY-MM-DD.log`；异常日志仍是覆盖式
  （只留最近一次异常）。保留天数由 `WM_FLOW_LOG_DAYS` 统一设定（单位天，
  可填 7 / 3 / 1，超期归档自动清理，0 = 不清理），不会无限增长。

### 无人值守（搬到手机上不管了）

- **只提交代码也会更新**：代码版本独立轮询，不依赖私有库有没有新提交；
  你告诉我问题、我修好并 push，手机最长约 1 分钟内自己同步、迁移、重启服务。
- **失败能自愈**：某轮失败记下的版本只在退避窗口内跳过，窗口过后会重新尝试；
  网络恢复但远端没有新提交也不会永久卡死。窗口内最多 3 轮，用尽后进入长退避并记异常日志，
  不无限静默重试。
- **不会自己死掉**：崩溃重启预算按时间窗口重置，代码一更新立刻清零；
  单实例锁由系统持有，进程被杀 / 手机重启会自动释放。
- **GIT 也算地址访问**：`fetch` / `push` / `clone` / `pull` 全走同一个同域名节流闸门，
  两次访问间隔固定 3~5 秒，状态落盘、跨进程共享；域名写法归一
  （`api.github.com` 与 `github.com` 算同一个），自己的本地地址豁免。
  一轮的实际耗时可能长于 10 秒，这是间隔规则的必然结果，不为提速关掉。
- **手机开机自启仍需要你放一次脚本**：进程被系统杀掉或手机重启后，程序内无法自我拉起，
  这是手机系统的限制。Termux 可装 `termux-boot`，把「进入公共库目录 → `python run.py`」
  放进开机启动目录；之后就不再需要管它。具体目录按项目根相对路径自己拼。

### 四条边界

1. **更新判断恒为 GIT 双源拷贝**：只看拷贝下来的版本有没有变化，
   不看任何信号文件，也没有可切换的开关。
2. **回写有并发保护**：基于本源最新 commit 造提交再 push；若别的提交抢先（非快进被拒），
   就重新拉最新、以本地迁移结果为基准重合并，最多 3 轮（单轮超 5 秒也重来），
   再切备用源同样 3 轮；全失败报「数据拉取异常」，本地最新监控记录不会丢。
   备用源就是另一个私有库地址，不需要任何额外配置。
3. **`update.cfg` 是私有库里的接口文件：一切接口地址都在这里对接，别删**：
   真实值放私有库根目录并进私有库 git，公共库只留 `update.cfg.example` 模板；接口地址只在此一处。
   启动器只拷不生成。改了私有库那份，手机下一轮自动同步并重启重新装配。当前装的是纯 GIT 读写。
   数据库 / 第三方数据接口是**以后扩展的方向，现在不用填任何配置**
   （当前填了只会明确报「未实现」）。
   判断层与读写层是分开的两套：将来真接接口只换数据后端 Store
   （在 `updater.make_store` 注册适配器），GIT 双源拷贝的逻辑一行都不用动。
   公共库根的 `update.cfg`（本地拷贝）、`data/`、`bootstrap.cfg` 都不进公共库 git。
4. **同域名访问间隔一体适用**：GIT 的 fetch / push / clone / pull 都是地址访问，
   统一过闸门、按域名归一、状态落盘跨进程共享；判断层、代码同步、数据读写、
   启动器首跑都不会绕过。

## 二、部署流程（全新机器 / 手机 Termux / QPython）

### 准备

- 装 Python 3 与 git（Termux：`pkg install git python ca-certificates`）。
- **两个私有库地址各有一条能免密 `git fetch` / `git push` 的通道**：本机已保存 git 凭证就直接用
  HTTPS（如 `https://github.com/你的账号/你的私有库.git`）；手机 / 没存凭证的机器用 SSH。
  两端是同一个库的两份镜像，不要求同一种方式，谁通就用谁。
- **不需要任何密钥 / API / 第三方接口**：读文件、上传回写全用 git 指令，
  凭据由本机 git 自己保管，程序不读也不存。
- **不用填任何仓库地址**：私有库根目录的 `update.cfg` 就是真实配置，clone 下来自带。
  `bootstrap.cfg` 只管本机把公共库放哪，可有可无。

### 步骤

```bash
# 1. 先克隆【私有库】（不是公共库）：启动器和真实配置都在里面
git clone <你的私有库地址> bot
cd bot

# 2. 一键启动（真实配置 update.cfg 已经随私有库带过来，零手填）
python bootstrap.py
```

`bootstrap.py` 只做四件事，然后拉起 `run.py`：

1. 克隆 / 更新公共库：主库失败自动改从备用公共库拷，两个都失败才报错；
   目标已有公共库（含 `.git`）时对两个源依次 `pull --ff-only`。
2. 把私有库根目录的 `update.cfg` **原样拷**到公共库根目录（不生成、不改写）。
3. 本地没有 `wm-bot/python/data/config.txt` 时，从私有库
   `services/wm-bot/config.txt` 拷一份过来（含真实密钥，不用手工填）。
4. 拉起 `python run.py`（Windows 前台等待、其余平台 `execv` 替换），进入上面的「运行流程」。

### 部署完成怎么确认

- 控制台出现「统一 RUN 启动」和「启动自检通过」；群里 @ 机器人发 `帮助` 有回复。
- 群白名单 `wm-bot/python/data/groups.txt` 是本地文件、不进 git，也不在私有库里：
  换设备要自己拷过去或新建（每行一个 `group_openid`），不建＝默认不监控任何群。
- 之后重新登录 / 换天开机，只需在公共库目录运行 `python run.py`；
  也可以再跑一次 `python bootstrap.py`（重新 pull + 重拷 `update.cfg`），效果相同。
  手机长期挂机见上面「无人值守」一节里的一次性开机自启做法。

### 安全

- 私有库**永久 Private**：别改 Public、别加陌生合作者，git 历史里存过的密钥不可逆。
- 仓库地址与真实配置**只进私有库**、不进公共库；公共库根的 `update.cfg` 是本地拷贝，
  和 `bootstrap.cfg` 一样绝不提交到公共库。
- 本机 git 凭证由系统保管，程序不读取、不落盘、不写进任何配置。
- 换设备时凭证与群 openid 跟着机器人 AppID 走、不用改值；
  但同一 AppID 只能有一条长连接，换手机跑之前先关掉电脑上那个 `run.py`。

<font color="red"><b>查日志：在 `wm-bot/python/` 跑 `python view_flow_log.py [日期]` 打印当天/指定日期，`--list` 列日期，`--tail 30` 看末尾，`--log bot|trace|updater` 选日志；独立零依赖，手机可用。</b></font>
