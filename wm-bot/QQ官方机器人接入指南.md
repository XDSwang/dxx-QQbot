# QQ 官方机器人接入指南（Warframe Market 查询 WM/ZK）

本指南带你把 `wm-bot/python/qq_bot.py`（官方模式）跑起来，让群友在**普通 QQ 群**里 `WM <物品名>` 即可查价（默认要 @机器人；在群资料页把「机器人可获取的群聊消息范围」设为「获取群内全部消息」后可免 @）。

> 前提：走**腾讯官方开放平台 q.qq.com**，正规、无封号风险；不是 OneBot 逆向方案。
> 本机只需 Python 3（标准库即可，**无需 pip 安装任何包**）。
> **没有 `.bat` / `.sh` 启动脚本**：运行只有 `python qq_bot.py` 一条命令；
> 配置：`wm-bot/python/config.txt` 是可上传的**纯净模板**（凭证留空），
> 真正生效的是 `wm-bot/python/data/config.txt`（由模板复制后填写，整个 `data/` 已被 `.gitignore` 排除）。

---

## 一、整体连接拓扑

```
QQ 群成员  ──@机器人──▶  普通 QQ 群
                                  │
                                  ▼  群 @消息事件
                         腾讯官方机器人网关 (wss://api.bot.qq.com)
                                  │
                                  ▼  WebSocket 推送事件
                         qq_official.py  (TokenManager 自刷 access_token)
                                  │
                                  ▼  调用 WM 查询逻辑
                            qq_common.make_handler  →  wm.py (查价/缓存/节流)
                                  │
                                  ▼  被动回复（带 msg_id，取自事件 d.id）
                          回消息到群里 @ 提问者
```

凭证位置：**appid / clientSecret 写进 `wm-bot/python/data/config.txt`**（模板在 `wm-bot/python/config.txt`，别填在模板里）；脚本不打印 secret、日志里也不含。

## 二、在 q.qq.com 创建机器人（拿 appid / secret）

1. 浏览器打开 **https://q.qq.com**，用你的 QQ 扫码登录。
2. 进入「**机器人 / 开发**」→「**创建机器人**」，填名称、头像、简介并提交。
   （「设置 AI 服务 / 服务接入」那步**直接跳过**：我们是原创机器人，自己跑 `qq_bot.py`。）
3. 管理页「**基础信息 / 凭证**」抄下：
   - **appid**（一串数字）
   - **clientSecret**（一串字符串，**等同账号凭证，切勿外泄**）
4. 把 `wm-bot/python/config.txt` 模板复制一份到 `wm-bot/python/data/config.txt`（没有 `data/` 就新建），
   用记事本打开 `data/config.txt`，把 `WM_QQ_APPID` / `WM_QQ_SECRET` 两项填好、保存。

> 平台那些「公开服务 / 群管理权限 / 白名单群聊」开关**都不用开**；新版管理端加群时的
> 「设置权限」同理保持最小（群成员即可，不必管理员）；「服务器 IP 白名单」务必**留空**，
> 否则电脑 / 手机换网络就会被挡。
> **真正要开的是手机 QQ 里【群资料页 → 机器人设置】的两个开关**（按群单独开，见第七节）：
> ①「机器人可获取的群聊消息范围 = 获取群内全部消息」→ 免 @；②「机器人主动在群聊内发言」→ 监控主动推送。
> 默认 intents 已含全部这些事件（见第八节，`1<<25` 一位覆盖 @、全量群消息、单聊、通知开关与进退群）。

## 三、把机器人拉进你的普通群（群主操作）

> 群相关的完整流程（平台「添加群号授权」、手机 QQ 入群时的「设置权限」、
> 数字群号与 group_openid 的区别、白名单与排障）单独写在
> **`QQ群接入与授权操作说明.md`**，本节只给最简路径。

1. 进入你想接入的**普通群** → 群设置 →「**群机器人 / 添加机器人**」。
2. 选择刚创建的机器人，确认添加。
3. 群里出现这个机器人成员。**只有加进群，它才能收到该群的 @消息。**

> 2026 年官方机器人已支持普通群，并非只能用频道。入口可能随客户端版本变化，以当前界面为准。

## 四、获取该群的 group_openid（白名单要填它）

机器人只回复**白名单里写着的群**。`data/groups.txt` 填的是 **group_openid**（字符串，不是数字群号）。两种拿法：

**方法 A —— 平台后台查**（新版管理端不一定提供这个列表，找不到就直接用方法 B）
在 q.qq.com 机器人管理页找「已加入的群 / 群列表」，对应字段即 `group_openid`。

**方法 B（最稳）—— 借运行日志看**
- 把 `data/config.txt` 里 `WM_QQ_ALLOW_ALL_GROUPS` 临时改成 `1`（或直接跑 `python qq_bot.py --allow-all-groups`，不改文件），
- 在群里**从 @ 列表点选机器人**发 `WM Boltor Prime`，让它成功回一条，
- 打开 `data/bot_flow.log`，从 `群@消息 group_openid=...` 那行抄下字符串，
- **抓完把开关改回 `0` 并重启**（否则就是监控所有群）。

> 白名单是**纯手工**的：程序不会自动打印提示、更不会自动写入 openid（那会绕开你的设置规则）。

## 五、写入白名单 data/groups.txt

用记事本打开**脚本同目录**的 `data/groups.txt`（整个文件夹拷到手机 / 别的盘也一样）：
```
EXAMPLE_GROUP_OPENID_A1B2C3D4E5F6      # 我的交易群（示例，换成自己抓到的字符串）
A1B2C3D4E5F60718293A4B5C6D7E8F90      # 朋友群
```
- `#` 开头为注释，行内 `#` 之后为备注；
- group_openid 是一串字母数字，**不是** QQ 里显示的数字群号（如 `123456789` 这类纯数字不能用）；
- 只有写进去的群才被监听，其它群一律静默；改完**重启程序**生效。

## 六、启动（只有一条命令）

在 `qq_bot.py` 所在目录执行（整个文件夹拷到任意位置都行，路径不写死盘符）：

```bash
python qq_bot.py
```

Windows / 手机 Termux / QPython **完全一样**，不需要任何启动脚本、不需要设环境变量。
启动后 stderr 会打印：
```
[official] 官方 QQ 机器人启动，appid=..., intents=33554432
[official] 群白名单已加载 2 个：['...', '...']
[official] 群内 @机器人 后发送「WM <物品名|中文名>」或「ZK <武器名>」即可查询；「翻译 <名称>」查名称中英对照；「翻译 同步」拉全量词库；「/报错 WM <名称>」强制刷新。
```

挂机常驻：Termux 用 `termux-wake-lock` + `tmux`；服务器用 `systemd` / `tmux`；Windows 保持终端最小化即可。

## 七、群内使用方式

在白名单群里，**默认要 @机器人**才触发。要免 @、并让监控能主动推，请在手机 QQ 打开
**群资料页 → 机器人设置**（点机器人头像进设置），按群单独开这两个开关：

| 设置项 | 截图里的样子 | 作用 | 触发事件 |
|---|---|---|---|
| 机器人可获取的群聊消息范围 | 副标题「**获取群内全部消息**」 | 群里每条消息都推给机器人，`WM Boltor Prime` / `警报` 直接发即可，不用 @ | `GROUP_MESSAGE_CREATE`（官方文档「群消息（全量模式）」） |
| 机器人主动在群聊内发言 | 蓝色开关，小字「机器人可主动发消息，如定时任务推送等」 | `监控 <词>` 的定时推送能主动发到群里 | 开启 `GROUP_MSG_RECEIVE`／关闭 `GROUP_MSG_REJECT` |

> 两个开关**互不替代**：第一个管「听得到所有消息」，第二个管「没人问也能主动说」。
> 每个群、每个单聊用户都要单独开一次；事件体字段：群 `group_openid` + `op_member_openid`，
> 单聊 `openid`。`WM_QQ_INTENTS` 保持 `33554432 (1<<25)` 不用改。
> 没开第一个时仍按 @ 用法；代码两种事件都接、都走同一套 handler。
> 全量模式会收到所有群消息，请务必保持 `data/groups.txt` 白名单（只回复白名单群），
> 闲聊仍静默，不会刷屏。
>
> **回复方式（重要）**：免 @ 的全量消息（`GROUP_MESSAGE_CREATE`），机器人是**单纯往群里发一条
> 普通消息**——不 @ 任何人、也不显示「引用某条消息」（`WM_FULLMSG_ACTIVE=1`，不带 `msg_id`）；
> 只有用户 @ 机器人时才走被动引用回复（带 `msg_id`）。两条通道互为兜底：主动没权限回退被动，
> 被动窗口被拒回退主动，都不会不回话。
> 也正因为每条群消息都收得到、都回得出去，**监控内容可以借任意一条聊天消息发出来**：
> 主动推送发不出去时先暂存，下一条群消息（哪怕只是闲聊）就把它带出去，效果等同推送，
> 受 `WS_ATTACH_GAP`（默认 20 秒）限频，不会刷屏。

| 群内发送 | 效果 |
|---|---|
| `WM Boltor Prime`（免 @ 时）或 `@机器人 WM Boltor Prime` | 查物品在售订单（最多 15 条，按 **游戏中 → 在线 → 离线** 分组后再按价格从低到高）；回复是**一条消息**：价格卡片图（昵称按状态上色）+ 同条消息里可复制的中英文双 `/w` 指令文字 |
| `WM 螺钉步枪` | 中文名查询（先翻英文再查价），同英文效果 |
| `ZK Tigris` | 查紫卡武器 Tigris 的拍卖列表 |
| `翻译 Boltor`（或 `翻译 螺钉步枪`） | 只做名称中英对照，返回官方英文与灰机中文 wiki 双链接 |
| `翻译 同步` | 联网拉全量中英对照词库（约 3447 条，一次即可，之后查询不再联网） |
| `/报错 WM Boltor Prime` | 强制忽略缓存重查一次（数据异常时用；失败会明确报错、后台继续重试） |

- 私聊直接发 `WM <名称>` / `ZK <名称>` / `翻译 <名称>` 即可（不受白名单限制）；
- 闲聊不含触发词 → 静默，绝不刷屏；
- 回复带 WM 完整网址来源、订单列表、英文名/中文名；
- **交易回复 = 一条消息（上卡片图 + 下可复制字符串）**：价格列表画成卡片图，卖家昵称按状态上色
  （**游戏中红 / 在线蓝 / 离线灰**），行首 `[游戏中]`/`[在线]`/`[离线]` 是状态标签；
  中英文两条游戏内 `/w` 指令作为**纯文本排在图片下方**，长按即可复制，**不带任何来源备注**。
  默认走 `msg_type=2` Markdown 消息（官方 2026/04/23 起自定义 Markdown 对单聊/群聊全量开放，
  不用申请模板）：图片**首选固定公网 URL + 覆盖式上传**，网盘 / Git 仓库里只有一张
  `card.png` 反复覆盖，URL 永不变、不占免费额度，客户端按图片标签自动解析；
  没配覆盖式才退回官方**素材管理**三步上传换 `qqbot-media://`。
  ★ **图下面只放那两条 `/w`，不重复正文**：卡片图里已经画好标题、行情统计、排序说明、
  订单列表、来源网址，再打一遍就是用户截图里那种重复；只有「文字 xxx」纯文字回退才输出全文。
  **素材/上传失败时不会发出「无图纯文字」**，而是直接回退富媒体通道把卡片图发出去。
  `WM_QQ_MARKDOWN = 0` 可切回富媒体 `msg_type=7` + `content` 图文混排；
  服务端拒绝混排（如 22006）或设 `WM_QQ_MIX_MESSAGE = 0` 时退回「图一条 + 文本一条」，`/w` 不会丢。
  ⚠️ **Markdown 文字没有颜色语法**，红蓝灰只在卡片图里，图片出不来颜色就没了。
- **「翻译」只给名称对照，不提供 wiki 正文**：获取方式 / 锻造材料 / 数值等内容机器人抓不到
  （两站 Cloudflare 反爬），回复里会给两个 wiki 链接，请自己点开看。

## 八、配置速查（全部在 data/config.txt）

用记事本改「名称 = 值」，保存后重跑 `python qq_bot.py`；文件内每项都有中文注释。

| 名称 | 默认 | 说明 |
|---|---|---|
| `WM_QQ_BACKEND` | `official` | `official` 官方 / `onebot` 社区方案（备选） |
| `WM_QQ_APPID` | 空（**必填**） | q.qq.com 的 appid |
| `WM_QQ_SECRET` | 空（**必填**） | clientSecret，敏感，勿泄露 |
| `WM_QQ_GROUPS_FILE` | `data/groups.txt` | 群白名单文件 |
| `WM_QQ_ALLOW_ALL_GROUPS` | `0` | `0` 只监控白名单群（正式）；`1` 临时全群（仅抓 openid） |
| `WM_CACHE_MINUTES` | `60` | 缓存新鲜度（**分钟**），改数字即可，如 `15` |
| `WM_API_BASE` | `https://api.warframe.market` | 数据源根地址；网络访问不了时填可用的代理 / 镜像 |
| `WM_HTTP_TIMEOUT` | `15` | 单次联网超时秒数；连不上立刻报错，不会让机器人卡住不回复 |
| `WM_QQ_API_BASE` | `https://api.bot.qq.com` | OpenAPI 根地址（一般不用改） |
| `WM_QQ_INTENTS` | `33554432` | 事件订阅掩码（`1<<25`，已含群@/群全量/单聊/通知开关/进退群；免 @ 与主动发言是**群资料页开关**，不用改这里） |
| `WM_FULLMSG_ACTIVE` | `1` | 免 @ 全量消息的回复方式：`1`=单纯发一条普通群消息（**不 @ 人、不引用**），`0`=被动引用回复 |
| `WM_QQ_MIX_MESSAGE` | `1` | `WM_QQ_MARKDOWN = 0` 时：交易回复「卡片图 + `/w` 指令」合成**一条**富媒体混排消息；`0`=退回图一条 + 文本一条 |
| `WM_QQ_MARKDOWN` | `native` | **默认开**。一条 `msg_type=2` Markdown 消息 = 卡片图 + 图下两条 `/w`；**图里已有标题/正文/来源，文字区不重复**；`native` 原生 / `template` 审核模板 / `auto` / `0` 关（回退 `msg_type=7`）。2026/04/23 起自定义 Markdown 对单聊/群聊所有机器人开放，无需模板 |
| `WM_QQ_MD_FALLBACK` | `1` | Markdown 发送失败自动回退富媒体/纯文本；设 `0` 只看平台返回码、不再补发（**没图例外**：仍会回退发图，绝不发无图纯文字） |
| `WM_QQ_MD_IMAGE_URL` | 空 | **首选通道**：那一张 `card.png` 的固定公开地址；配了覆盖式上传时也必须填这个作为引用 URL |
| `WM_QQ_MD_IMAGE_PUT_URL` | 空 | 覆盖式上传端点（网盘 WebDAV / R2 / 对象存储）；PNG 二进制 PUT 到这个固定地址，永远只有一张图 |
| `WM_QQ_MD_IMAGE_PUT_TOKEN` | 空 | 上传鉴权头，原样写进 `Authorization`（如 `Bearer xxx`）；公开可写时留空 |
| `WM_QQ_MD_IMAGE_PUT_METHOD` | `PUT` | 个别网盘用 `POST` 覆盖时改这里 |
| `WM_QQ_MD_GITHUB_REPO / TOKEN / PATH / BRANCH / API / RAW` | 空 | 方式 B：GitHub/Gitee 仓库存一张图，Contents API 覆盖；不填 `RAW` 自动用 raw 地址。**token 只写 `data/config.txt`** |
| `WM_QQ_MD_IMAGE_BUST` | `1` | 固定 URL 覆盖后给链接加 `?v=<图片哈希>` 破客户端/CDN 缓存；存储仍只有一张图，设 `0` 关 |
| `WM_QQ_MD_MEDIA_MAX` | `3` | **清理阈值**：官方素材默认只留 3 张（平台上限 100）；每上传一张新卡片就 `DELETE` 掉多余的旧素材，平台长期只占 1~3 张配额。填 `1` / `3` / `5` 都行（范围 1~95），同一张卡片按 SHA1 命中缓存不上传、不触发删除 |
| `WM_QQ_MD_TEMPLATE_ID` | 空 | 模板 Markdown 用：后台创建模板 → 提交审核 → 拿 ID，再把 `WM_QQ_MARKDOWN` 设 `template` |
| `WM_QQ_MD_IMAGE_WIDTH` | `618` | Markdown 图片显示宽度（px），高度按卡片原图比例自动算 |
| `WS_ACTIVE_MIN_GAP` | `300` | **周期**主动推送最小间隔（秒），内容不变一律不重发，防刷屏与官方频控 |
| `WS_PRIORITY_TYPES` | `alerts,events` | **全局默认**主推栏目；可写中文 `警报,活动,入侵`，写 `off` 关掉主推。聊天指令设的开关按会话覆盖它 |
| `WS_PRIORITY_MIN_GAP` | `60` | 主推防抖最小间隔（秒）；主推**不受** `WS_ACTIVE_MIN_GAP` 的 300 秒限制 |
| `WS_PRIORITY_SKIP_IN_FULL` | `1` | 周期全量推送剔除主推栏目，避免同一条警报被推两遍；`0` 关 |
| `WS_SWITCH_FILE` | `data/ws_switches.json` | 聊天指令「活动=开启」等开关的存盘位置；**设置一次重启后仍在**，不用改配置 |
| `WS_SWITCH_PERSIST` | `1` | `1`=存盘（默认）；`0`=只本次运行有效、不写盘 |
| `WS_AUTO_PRIORITY` | `0` | 启动时对 `groups.txt` 白名单群批量自动注册主推。**默认关**；一般改用聊天指令，更灵活且能记住 |
| `WM_SSL_CAFILE` | 空 | 手机端 HTTPS 报证书错误时，手动指定 CA 文件路径（pem/crt）；留空则自动探测 |
| `WM_SSL_NOVERIFY` | `0` | `1`=强制不校验 HTTPS 证书（**不推荐**，有中间人风险）；留空/0 时仅在找不到任何 CA 时临时兜底并打印警告 |

> 同域名 3~5 秒节流、1/3/7 分钟重试、全失败 1 小时是**硬规则**，不提供配置项、不能调小。
> 刷新失败时用户只等 1 次尝试就收到明确报错，重试在后台继续，主线程不阻塞。

## 八、世界状态查询 / 监控（可选功能）

机器人内置了**星际战甲（国际服）世界状态**查询与监控，数据源默认抓 **wf.wiki 的实时世界状态页**
（`worldstate.wf.wiki`，无 Cloudflare、程序化可直连、数据实时；世界状态以 JSON 内嵌在页面 RSC 流里）。
也可切回旧的 `api.warframestat.us` 系（`WM_WS_SOURCE=warframe`，常被 Cloudflare 拦成 403）。
完整说明见仓库根 `README.md` 的「世界状态查询」章节，这里只列与接入/权限相关的要点。

> wf.wiki 覆盖：平原昼夜（希图斯 / 奥布山谷 / 魔胎之境 / 双衍王境 / 扎里曼）/ 裂缝 / 钢铁裂缝 /

> **仲裁**来自 `arbi.wf.wiki` 的仲裁轮换表（两张静态 JSON，本地按时间推算，7 天同步一次、平时零请求）。
> **仍不提供**：信使前哨 / 集团任务 / 建造进度（DE 原始数据没有；单条查询会如实提示「该数据源不提供」）。

**查询（被动，秒回）**：群里 @ 机器人发 `警报` / `平原` / `突击` / `仲裁` / `裂缝` / `钢铁裂缝` /
`赏金` / `赏金轮换` / `信条` / `终幕` / `加成` / `活动` / `入侵` / `电波` / `虚空商人` / `瓦奇娅` /
`特惠` / `新闻` 任一词即可；`平原` 一次给五处昼夜，**每处时间后紧跟它自己的赏金任务板**
（希图斯→Ostron / 奥布山谷→索拉里斯 / 魔胎之境→英择谛；单发「希图斯」等单词也带）；
`裂缝` / `钢铁裂缝` 分成**常规星球（上）**和**九重天（下）**两块，各自按
**古纪 → 前纪 → 中纪 → 后纪 → 安魂 → 全能** 排序、同档再按剩余时间升序，
九重天（XX比邻星域）单独成组不与常规星球混排；
`全部` 给所有栏目（栏目多时自动精简每栏条数，裂缝精简也保证两块各露面 2 条，保证一条消息发得完），
`计划` 查看各数据的到期时刻表。记不住这么多词？直接发 `帮助`（或 `?` / `菜单`）会调出**全部指令一览**（查价 / 紫卡 / 翻译 / 世界状态 / 监控 / 计划），不用背。机器人读本地缓存即时回复，**缓存未到期就是零网络请求**；
更新按数据自身的到期时间驱动，**不轮询、不反复查询**：抓取时记录 `fetched_at`，把 `expiry` / `activation` /
`timeLeft`（相对时长换算成绝对到期时刻）去重升序写进 `worldstate.json` 的 `queue`，后台长睡到队首那一刻，
只发**一次**全量请求、重排队列后继续睡。例：虚空商人未到访时队首就是他下次抵达时间（可能十几天），
期间一次接口都不打，抵达 / 离场那一刻才更新一次。

**回复形式（默认一律卡片图）**：所有回复（世界状态 / WM 查价 / 紫卡 / 翻译 / 帮助）都渲染成
**白底卡片图**（分组标题带色条、剩余时间右对齐、超长自动双栏或分页）。
- 图里的字在 QQ 里**选不中、复制不了**。但 **WM 交易回复是例外**：英中两条 `/w` 指令是
  同一条消息里的纯文本，随卡片图一起发（图文混排合成**一条**，不再是图一条 + 字符串一条），
  直接长按复制，不用加前缀。要复制其它正文（裂缝节点名等）时，在指令前加「文字」两字：
  `文字 裂缝` / `文字 WM Boltor Prime`（对 WM、紫卡、帮助同样生效）；`图 xxx` 则显式要求出图。
- 想永久改回按长度自动 / 纯文字：`data/config.txt` 里 `WM_WS_CARD = auto|off`（默认 `always`）。
- **默认发送 = Markdown 消息（`msg_type=2`，`WM_QQ_MARKDOWN = native`）**：一条消息里
  「完整卡片图」+「图片下方两条可复制 `/w`」；标题、统计、排序、订单、来源都在图里，
  **文字区不重复正文**（`markdown.content` 只有图片标签 + 两行 `/w`）。图片是本地 Pillow 渲染的 PNG。
  **首选通道 = 固定公网 URL + 覆盖式上传**：网盘 WebDAV / R2 / 对象存储放一张 `card.png`
  （通用 `PUT` 到 `WM_QQ_MD_IMAGE_PUT_URL`，公开地址填 `WM_QQ_MD_IMAGE_URL`），
  或用 GitHub/Gitee Contents API（`GET` 取旧 `sha` → `PUT` 同路径带 `sha` 覆盖），
  公开链接固定为 `raw.githubusercontent.com/<repo>/<branch>/<path>`。
  无论查多少次**存储里只有一张图**，不会攒出过期素材、不消耗免费额度；
  `WM_QQ_MD_IMAGE_BUST = 1` 给 URL 加 `?v=<图片哈希>` 破客户端/CDN 缓存（不新增对象）。
  同一张卡片按 SHA1 记住，内容没变就不重复上传。
  **兜底通道 = 官方素材管理**：`POST /v2/media-images/prepare`（file_size / md5 / sha1 /
  content_type）→ `PUT <presigned_url>` 直传二进制 → `POST /v2/media-images/complete`
  拿 `qqbot-media://` 引用。素材上限 100 张、90 天过期，故按 SHA1 缓存并自动删最旧。
  **真机实测**：`python md_probe.py`（dry-run 看「一张图 + 一个内容字符串」请求体与网页预览）
  → `python md_probe.py --send --group <openid> --image overwrite`，看 QQ 是否真渲染公网图；
  不渲染换 `--image media` 用官方素材对照。官方未保证任意公网 https 链接都放行。
  `WM_QQ_MARKDOWN = 0` 则走原来的富媒体路径：`POST /v2/groups/{group_openid}/files`
  二进制直传拿 `file_info` → `msg_type=7` + `media.file_info`（WM 回复同条带 `content`，
  多张卡片时只把文字并进最后一张）；被动回复照旧带 `msg_id`，仍在 5 分钟窗口内。
  两条路径失败都会自动回退纯文本，不会不回话。
- 依赖 **Pillow + 中文字体 + `render_card.py` 文件**（微软雅黑 / 思源 / Noto / 文泉驿任一）。
  任一缺失，或上传/发送失败（如机器人没发图权限），都会**自动退回纯文字**。
  手机端表现就是「回复变成一大段字、红/蓝/灰昵称全没了」：启动时
  `[card] 图片能力自检` 会指出缺哪一样，Termux 用
  `pip install pillow` + `pkg install noto-cjk-fonts` 修，或用 `WM_CARD_FONT` 指定字体路径。
  ⚠️ Markdown 文字本身**没有颜色语法**，红蓝灰是画在图里的，别指望纯文字阶段有颜色。
- 只用 OpenCV 是不行的：`cv2.putText` 在 4.x 下中文全变 `?`，5.x 虽支持中文但字体不可换、emoji 仍是 `?`。

**★ 发消息直接开关主推（推荐，不用改配置、不用重启）**：在群里或私聊直接发：

| 指令 | 效果 |
| --- | --- |
| `活动=开启` / `警报=开启` | 该栏目**自动纳入本会话监控**并设为主推，新条目立即单独推；不用再发「监控 活动」 |
| `活动=关闭` / `警报=关闭` | 该栏目不再主推，**周期全量推送里也剔除** |
| `主推=开启` | 一键开启默认主推（警报 + 活动）；`全部=开启` 则所有栏目 |
| `主推状态` | 查看本会话当前监控栏目、主推栏目、手动开/关了哪些 |

也支持 `alerts=on` / `events=off` / 全角 `活动＝开启` / `活动 开启` / `关闭 警报`，
一条消息还能写多组：`活动=开启，警报=开启` 或 `活动=开启 警报=关闭`。
**设置按会话保存到 `data/ws_switches.json`，重启后 `load_switches()` 自动恢复并重新注册监控**，
不必重发；不同群 / 不同私聊互不影响，也**不会覆盖**你手动 `监控 <词>` 加的栏目。
发 `停止监控` 会停止本会话全部推送**并清除该会话已保存的开关**；想单独停某一项用 `活动=关闭`。
`WS_SWITCH_PERSIST = 0` 可改成只本轮运行有效、不写盘，`WS_SWITCH_FILE` 可改存盘位置。

**监控（主推 + 周期兜底 + 随任意消息附带）**：发 `监控 <词>`（如 `监控 警报` / `监控 全部`）后，
机器人每 `WS_PUSH_SECONDS`（默认 10 秒）**检查**一次世界状态（只读本地缓存，不额外打接口）；
发 `停止监控` 停止。注意 10 秒是检查节拍，**不是发送周期**。
`监控 <词>` 是一次性的会话注册（重启清空）；想要「设置一次一直在」就用上面的 `活动=开启` 等开关指令。
另有 `WS_AUTO_PRIORITY = 1`（默认 `0`）可在启动时对 `groups.txt` 白名单群批量自动注册，
但它每次重启都按配置重开、不吃「停止监控」，一般不如聊天指令灵活。
1. **先试主动消息**：默认渲染成卡片图发送（`/files` 上传 + `msg_type=7`，不带 `msg_id`），
   发图失败才回退纯文本。前提是该群在【群资料页 → 机器人设置】打开了
   **「机器人主动在群聊内发言」**；没开时固定 `40034105 主动消息失败, 无权限`。
2. **警报 / 活动「主推」：新条目立即推**：这两个栏目时效性强（警报常带催化剂 / Forma 奖励），
   等 5 分钟周期就晚了。出现新警报 / 新活动、或奖励 / 描述变化时，**立刻单独发一条精简消息**
   （`🚨 世界状态主推 · 新增 N 条`），只装发生变化的栏目，**不受 `WS_ACTIVE_MIN_GAP` 300 秒限制**，
   只受 `WS_PRIORITY_MIN_GAP`（默认 60 秒）防抖。刚开监控只记录当前状态作为基线，**不补发历史**；
   条目结束静默消化，不推「活动结束」。推送失败会保留基线自动重试，并同时进暂存随下一条群消息
   带出，不会把新警报悄悄吞掉。同一轮主推成功就不再发周期那条，避免连着两条刷屏。
3. **周期推送：内容不变不重发**：其余栏目按内容变化推送，且距上次推送超过
   `WS_ACTIVE_MIN_GAP`（默认 300 秒）才发。签名会**剔除「剩余：5分30秒」这类倒计时**，
   倒计时跳动不再算「内容变了」——旧版因为签名含倒计时，实际会每 5 分钟固定刷一条，现已修复。
   周期推送默认剔除主推栏目（`WS_PRIORITY_SKIP_IN_FULL = 1`），避免同一条警报被推两遍。
   官方主动消息有频控（单关系 `20 qpm`、**每群每天最多 1000 条**），别把 `WS_ACTIVE_MIN_GAP`
   调到 0，也别把 `WS_PUSH_SECONDS` 当发送周期。
4. **发不出去就攒着，随任意消息带出**：内容进暂存区，等本会话里有人发消息时，以
   `📬 监控推送（主动消息受限，随本次消息附带）` 一段拼在回复末尾，**跟正文同一张卡片图**发出去。
   开了「获取群内全部消息」后群里任意一条消息都能当这个窗口，不必非等查询指令；
   被动回复有 5 分钟窗口，所以一定能送达——没开主动发言也不会白开监控。

   暂存规则（`data/config.txt` 可调）：保鲜期 `WS_ATTACH_TTL`（默认 1800 秒）、同一会话附带间隔
   `WS_ATTACH_GAP`（默认 20 秒，防连发重复）、最大长度 `WS_ATTACH_MAX_BYTES`（默认 2000 字节，按整行截断），
   总开关 `WS_ATTACH_ON_QUERY = 0` 可关掉附带。暂存按栏目分块，本次查询已包含的栏目会被剔除，
   不会把同一个「裂缝」块重复贴一遍。
5. 主动通道连续失败后**退避成 5 分钟探测一次**；一旦收到 `GROUP_MSG_RECEIVE` /
   `C2C_MSG_RECEIVE`（有人打开了主动发言开关），立刻解除退避并补推一轮，不用干等 5 分钟。
   失败日志同样按 5 分钟节流，不会刷满 `data/bot_flow.log`。
- 节奏是**写死的硬规则**，不提供配置：两次全量请求之间 **10 → 20 → 50 → 10 秒**循环节拍
  （`WS_STEP_GAPS`，只在到期点异常 / 队列为空时兜底），真正决定何时请求的是**队首那一条的结束时刻**；
  接口失败退避 **10 → 30 → 60 秒**，之后保持 60 秒继续重试，成功后归零。
- 可改的只有 `wm-bot/python/data/config.txt` 的「六、世界状态」段落：`WM_WS_SOURCE`（数据源：wfwiki 默认 / warframe / mock）、
  `WM_WS_WFWIKI_URL`（wf.wiki 页面地址）、`WM_WS_OFFICIAL_URL`（DE 官方突击端点）、`WM_WS_ARBI_URL` / `WM_WS_ARBI_TTL`
  （仲裁轮换表地址与同步周期，默认 7 天）、`WM_WS_API_BASE`（仅 warframe 模式的接口根地址）、
  `WM_WS_LANG`（语言，zh / en）、`WS_PUSH_SECONDS`（监控检查节拍）、`WS_ACTIVE_MIN_GAP`（周期推送最小间隔）、`WS_WAKE_MAX`（最长睡眠）、
  `WM_WS_CARD`（回复形式，默认 always 全出图 / auto / off）、`WS_ATTACH_ON_QUERY`（是否随查询附带监控）、
  `WS_EXPIRY_GRACE`（到期宽限）、`WS_HTTP_TIMEOUT`（HTTP 超时）。
- 主推相关（`data/config.txt`「四点六(2)」）：`WS_PRIORITY_TYPES`（**全局默认** `alerts,events`，写 `off` 关）、
  `WS_PRIORITY_MIN_GAP`（主推防抖，默认 60 秒）、`WS_PRIORITY_SKIP_IN_FULL`（周期剔除主推栏目）、
  `WS_SWITCH_FILE` / `WS_SWITCH_PERSIST`（聊天指令开关的存盘位置与开关，默认存 `data/ws_switches.json`）、
  `WS_AUTO_PRIORITY`（启动批量自动注册，**默认 0**，一般用聊天指令代替）。
- 与 WM 的 3~5 秒同域名规则**一致而非例外**：每次 HTTP 前都走同一个 `pace_gate_ex`
  （内部就是 `pace_last_access` + `pace_record`，与 WM 共用 `pace.json` 文件），
  保证任何两次访问**同一数据源域名**（wf.wiki 或 warframestat.us）不短于 3~5 秒。

> 不想用这个功能？不配置、不发这些词，机器人就完全不会碰世界状态接口，零影响。

## 九、常见问题 / 排错

| 现象 | 排查 |
|---|---|
| 启动后一直刷 `[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate`，取 access_token 失败、反复重连 | **手机上的 Python 缺 CA 根证书**，不是网络问题也不是 QQ 接口问题；所有 HTTPS（取 token、发消息、查 WM、抓世界状态、连 wss 网关）会一起挂。① 最推荐：Termux 执行 `pkg install ca-certificates`，重跑 `python qq_bot.py` 即可，程序会自动找到 `$PREFIX/etc/tls/cert.pem` 并照常校验证书；② QPython / 其它 Python：`pip install certifi` 后把 `python -m certifi` 输出的路径写进 `data/config.txt` 的 `WM_SSL_CAFILE = /路径/cacert.pem`；③ 程序已内置兜底：自动探测 Termux / Android / Linux 常见 CA 路径，一个都找不到时会临时关闭证书校验让机器人先跑起来，并打印醒目警告（有中间人风险，建议按 ① 修复）。Windows / macOS 走系统证书库，不受影响 |
| 回复变成一大段纯文字、卡片图和「红/蓝/灰昵称」全没了 | **不是发送方式问题，是图片根本没渲染出来**。① 群里发「自检」，机器人直接回一段文字列出 `render_card` / Pillow / 字体 / Markdown 各部件状态（最省事）；或看启动日志 `[card] 图片能力自检`。② 缺文件 `render_card.py`（按 README 拷到手机时最容易漏这个）→ 补拷；缺 Pillow → `pip install pillow`；缺中文字体 → Termux `pkg install noto-cjk-fonts` 或用 `WM_CARD_FONT` 指定 TTF 路径。③ Markdown 文字本身没有颜色语法，颜色只在卡片图里，图不出来颜色必然没有。④ 只有主动发「文字 xxx」前缀才是正常纯文字 |
| Markdown 消息发不出去 / 报 `40035007`、`40035010` | 正常不会撞 `40035007`：清理阈值默认 3 张，每上传新图就删旧图（平台上限 100）。真撞到多半是换设备后平台留着历史素材，可用 `GET /v2/media-images` 查 `total` 后删，或调小 `WM_QQ_MD_MEDIA_MAX`；`40035010` = `qqbot-media://` 引用不属于当前机器人（换了 AppID 后旧缓存失效），删掉 `data/md_images.json` 重跑即可。两种情况都会**自动回退**富媒体图片/纯文本，不会不回话；想彻底关掉这条通道设 `WM_QQ_MARKDOWN = 0` |
| Markdown 里只剩文字、图片不显示（公网链接） | **官方没有保证任意公网 https 图片都被放行**，先别猜：`python md_probe.py` 看「一张图 + 一个内容字符串」的最小请求体和网页预览（不联网），再 `python md_probe.py --send --group <openid> --image overwrite` 真发一条到群里看效果。仍不显示就换 `--image media` 用官方 `qqbot-media://` 对照，或设 `WM_QQ_MARKDOWN = 0` 走富媒体图文混排。另外确认覆盖式上传的 `WM_QQ_MD_IMAGE_URL` 在浏览器里能直接打开、是 **https 且公开可读**（GitHub raw / jsDelivr 更稳，网盘分享页链接不行） |
| 覆盖式上传后图片一直是旧的 | 固定 URL 内容变了地址没变，客户端 / CDN 会缓存旧图。保持 `WM_QQ_MD_IMAGE_BUST = 1`（默认），链接会带 `?v=<图片哈希>` 让客户端拉新图；存储仍只有一张 `card.png`。若图床忽略查询参数，改用带版本路径的 GitHub raw 或清一次 CDN 缓存 |
| 启动报「缺少 WM_QQ_APPID / WM_QQ_SECRET」 | 还没把 `config.txt` 模板复制到 `data/config.txt`，或副本里这两项没填（只改模板不会生效），回第二、八节 |
| 群里 @ 机器人没反应 | ① 机器人是否已加进该群（第三节）；② 该群是否写进 `groups.txt`（第四、五节）；③ 是否**从 @ 列表点选**了机器人（只手打昵称不触发） |

## 十、安全与限制提醒

- **secret 等同账号凭证**：`data/config.txt` 内含 AppSecret；它所在的 `data/` 已被 `.gitignore` 排除（别手动加进版本控制），仍别截图、别发群、别传网盘；
  `groups.txt` 只放 openid，不含 secret。
- **官方被动回复频控**：被动回复（带 `msg_id`，取自事件 `d.id`）5 分钟内有效、每消息最多回 5 次；
  本场景"有人问才回"，不受影响。
  ⚠️ `event_id` 只支持 `INTERACTION_CREATE` / `GROUP_ADD_ROBOT` / `GROUP_MSG_RECEIVE` 等特定事件，
  普通群@/单聊用它会被拒（`40034027 请求参数event_id对应事件不能回复消息`）。
- **只收消息、闲聊静默**：群内默认 @机器人才触发；把群资料页「机器人可获取的群聊消息范围」
  设为「获取群内全部消息」后收到的是全量群消息（`GROUP_MESSAGE_CREATE`），但依然只对
  白名单群 + 触发词回复，闲聊照样静默（有暂存监控内容时才可能随消息带出，且受 20 秒限频）。
- **主动消息频控**：单关系 20 qpm、每群每天最多 1000 条；被动回复（带 `msg_id`）5 分钟有效、
  每消息最多回 5 次。非 @ 群消息被动回复若被拒，代码会自动去掉 `msg_id` 走主动通道重试一次。
- **白名单隔离**：只有你亲手写进 `groups.txt` 的群才被监控；任何"自动发现 / 自动加群"能力都未启用（设计铁律）。
